==============================================================================
 Calango — Dependency Analysis
==============================================================================
Atomistic modeling & simulation GUI (C++/Qt6 + OpenGL, with an embedded
CPython/ASE interpreter). This file documents every build-time and runtime
dependency, grouped by layer, with the version constraints Calango relies on.

Legend:  [required] must be present   [optional] enables a feature subset
         [build]    needed to compile  [runtime] needed to run

------------------------------------------------------------------------------
1. Toolchain / build system
------------------------------------------------------------------------------
[build][required] CMake .................... >= 3.21   (qt_add_executable, qt_add_resources)
[build][required] C++ compiler ............. C++20     (clang 14+/gcc 11+/AppleClang 14+)
                                             CMAKE_CXX_STANDARD 20, extensions OFF
[build][optional] sips + iconutil .......... macOS only, renders calango.icns from
                                             assets/calango/icon_osx.png (bundle builds)
[build][optional] macdeployqt .............. macOS, bundles Qt frameworks into Calango.app
[build][optional] linuxdeployqt / dpkg ..... Linux .deb packaging (packaging/linux)
[build][optional] ImageMagick .............. Linux only, scales assets/calango/icon_linux.png
                                             into the hicolor icon-theme sizes; without it
                                             only /usr/share/pixmaps/calango.png is installed

------------------------------------------------------------------------------
2. C++ / native libraries
------------------------------------------------------------------------------
[build+runtime][required] Qt6 .............. >= 6.4   (developed/tested against 6.9)
    Components (find_package(Qt6 ... COMPONENTS ...)):
      - Widgets ............ core GUI toolkit
      - OpenGLWidgets ...... accelerated 3D structure viewport (QOpenGLWidget)
      - Concurrent ......... background sampling / off-thread work
      - Svg ................ Brillouin-zone figure export (SVG)
    NOTE: QStyleHints::colorScheme() (System theme detection) needs Qt >= 6.5;
          guarded with QT_VERSION_CHECK so 6.4 still builds.

[build+runtime][required] OpenGL ........... 3.3 core profile
                                             (macOS provides 4.1 core; Linux via libGL)

[build+runtime][required] pybind11 ......... >= 2.12   (scoped_interpreter(PyConfig*))
                                             System package if found, else fetched
                                             (FetchContent, pinned v2.13.6).
                                             PYBIND11_FINDPYTHON=ON so it reuses the
                                             interpreter found by FindPython3.

    NOTE: Plotting uses Calango's own lightweight widgets (LinePlotWidget /
          MetricPlotWidget / PhononPlotWindow) drawn with QPainter. QCustomPlot
          is NOT a dependency (only referenced as a possible future swap-in).

------------------------------------------------------------------------------
3. Embedded Python interpreter (the .venv Calango ships/points at)
------------------------------------------------------------------------------
Calango embeds CPython and resolves its interpreter via CALANGO_PYTHON env ->
VIRTUAL_ENV env -> build-time CALANGO_DEFAULT_PYTHON. Verify with:
    ./calango --probe-python

[build][required]   Python ................. >= 3.9   (Development.Embed; tested 3.14)
[runtime][required] ASE (atomic-sim-env) ... >= 3.22  (tested 3.29.0)
                                             structure I/O, calculators, band paths
[runtime][required] NumPy .................. >= 1.23  (tested 2.5.1)   arrays / linear algebra
[runtime][optional] SciPy .................. >= 1.9   (tested 1.18.0)  interpolation / signal
[runtime][optional] spglib ................. >= 2.0   (tested 2.7.0)   symmetry detection
                                             (supports both the <2.5 dict and >=2.5
                                             dataclass dataset APIs)
[runtime][optional] matplotlib ............. >= 3.6   (tested 3.11.1)  offline figure export
[runtime][optional] paramiko ............... >= 3.0   (tested 5.0.0)   Remote Access SSH/SFTP panel
[runtime][required] imageio ................ >= 2.28  animation export (GIF + video writers)
[runtime][required] imageio-ffmpeg ......... >= 0.4   bundled ffmpeg binary the MP4/MOV/WebM
                                             writers encode through. Installed with imageio
                                             because every video format in the animation
                                             export dialog fails at import without it.
[runtime][optional] PyAlembic .............. Alembic (.abc) geometry-cache export.
                                             conda-forge ONLY: `conda install -c conda-forge
                                             pyalembic imath`. THE PACKAGE NAME AND THE IMPORT
                                             NAME DIFFER — it installs as `pyalembic` and
                                             imports as `alembic`, and the PyPI project named
                                             `alembic` is SQLAlchemy's database-migration tool,
                                             which shares the import name and nothing else.
                                             `pip install alembic` therefore appears to succeed
                                             and then fails inside the writer; `pip install
                                             pyalembic` fails outright, because no such PyPI
                                             project exists. AlembicExporter detects the
                                             collision at import and says so.
[runtime][optional] imath .................. Imath array types the PyAlembic API is written in
                                             terms of. Installed alongside pyalembic; the
                                             writer imports it directly.

  Core DFT / MLIP stack (required for the electronic-structure and MLIP
  workflows), not bundled by either installer — the user points a job at
  their own environment that has them (Preferences -> Python &
  Environments). GPAW has no conda-forge osx-arm64 build yet, so on Apple
  Silicon add it with `pip install gpaw`.
[runtime][required] MACE (conda: pymace) ... >= 0.3   (tested 0.3.16)  MLIP training / inference;
                                              pulls pytorch >=1.12, e3nn 0.4.4, cuequivariance-torch,
                                              torch-ema, torchmetrics
[runtime][required] GPAW .................... >= 24.1  (tested 25.7.0)  PAW/PW DFT: single-point,
                                              geometry-opt, band structure + PDOS
                                              (conda on x86_64; pip on osx-arm64)
[runtime][required] gpaw-data .............. PAW datasets for GPAW (conda-forge, all platforms)
[runtime][required] dftd4 .................. >= 3.6   Grimme DFT-D4 dispersion; the Python wheel
                                              dynamically links the dftd4 shared library.
                                              Coupled to any calculator via ASE's SumCalculator
                                              (pip: dftd4; conda-forge: dftd4-python)
[runtime][required] torch-dftd ............. >= 0.4   PyTorch DFT-D implementation backing
                                              mace_mp(dispersion=True)
[runtime][optional] xtb-python ............. >= 22.1  GFN1-xTB / GFN2-xTB / GFN-FF
                                              semi-empirical calculator. Runs IN-PROCESS via
                                              xtb.ase.calculator.XTB — no binary is launched —
                                              so it belongs to the INTERPRETER'S environment,
                                              not to $PATH.
                                              CONDA-FORGE ONLY, and this one really is:
                                              `pip install xtb` fetches a source distribution
                                              that builds xtb 6.5.1 with meson and needs a
                                              Fortran compiler plus MKL; it fails outright on
                                              macOS arm64. It also lags the newest CPython —
                                              conda-forge builds reach py313, so an embedded
                                              py314 interpreter cannot host it at all.
                                              Consequence: xTB is reached by pointing the
                                              engine at a Conda environment that has it
                                              (Preferences -> Python & Environments), which is
                                              what the calculator page reports on.
[runtime][required] phonopy ................ >= 2.20  symmetry-reduced phonon displacements,
                                              LO-TO splitting (NAC) and Γ-mode irrep labels

------------------------------------------------------------------------------
4. Optional job / calculator environments (user-selected conda env, NOT the
   embedded interpreter — chosen per run in the wizards / Preferences)
------------------------------------------------------------------------------
Additional DFT back-ends (GPAW is listed as core-required in section 3):
[runtime][optional] Quantum ESPRESSO ....... pw.x workflow (needs pseudopotentials)
[runtime][optional] SIESTA ................. ASE Siesta calculator (LCAO DFT)
[runtime][optional] VASP ................... ASE Vasp calculator (needs VASP_PP_PATH)

Interop / data sources (optional helpers):
[runtime][optional] pymatgen ............... Materials Project / structure interop
[runtime][optional] mp-api / Materials Project API key ... From Database browser
[runtime][optional] pubchempy or REST ...... PubChem molecule import

------------------------------------------------------------------------------
5. Version-pin quick reference (constraints Calango is validated against)
------------------------------------------------------------------------------
CMake            >= 3.21
C++              C++20
Qt6              >= 6.4  (System theme needs 6.5+)
pybind11         >= 2.12 (fetch fallback 2.13.6)
Python           >= 3.9
ASE              >= 3.22
NumPy            >= 1.23
SciPy            >= 1.9   (optional)
spglib           >= 2.0   (optional)
matplotlib       >= 3.6   (optional)
paramiko         >= 3.0   (optional, remote)
imageio          >= 2.28  (required, animation export)
imageio-ffmpeg   >= 0.4   (required, video encoding)
pyalembic                 (optional, .abc export; conda-forge only, imports as `alembic`)
imath                     (optional, .abc export; installed with pyalembic)
GPAW             >= 24.1  (required, DFT; tested 25.7.0)
dftd4            >= 3.6   (required, D4 dispersion; conda-forge: dftd4-python)
torch-dftd       >= 0.4   (required, MACE-MP dispersion head)
xtb-python       >= 22.1  (optional, GFN semi-empirical; conda-forge only, py<=3.13)
phonopy          >= 2.20  (required, phonon symmetry / NAC / irreps)
mace-torch       >= 0.3   (required, MLIP)
torch            >= 2.0   (required, MLIP)
torch-geometric  >= 2.4   (required, MLIP)
e3nn             >= 0.4   (required, MLIP)

Regenerate the embedded-env portion with:
    ./.venv/bin/python -m pip freeze
